12Security, privacy and store compliance

12.1 Apple: entitlement, review and the developer agreement

  1. Paid team. Family Controls (development) is only available to paid Apple Developer Program members [8]. A free Personal team can't use it.
  2. Distribution request. The Account Holder submits Apple's Family Controls (Distribution) request [7] for the app and each Screen Time extension [6]. Apple publishes no timeline; reports range from 2 days to more than a month, and extensions sometimes stay "Submitted" after the app is approved [97][98] Community. File it first.
  3. Primary purpose (developer agreement, "Family Controls Framework" clause). An app using the framework must have a primary purpose of parental supervision through Family Sharing, or of focus, productivity and personal device-usage management. It may not be used for ad blocking, by organisations, or to manage another adult's device. Usage data may be used only for those controls, never shared, used for ads or sold [23][24].
    • The agreement PDF of 29 October 2026 numbers this clause 3.3.3(P); Apple's March 2026 notice called it 3.3.3(Q) [102]. Cite it by title.
    Risk for apps whose main purpose is something else (for example fitness): present the app as personal device-usage management in the request, the store listing and the review notes, and make the feature prominent. Apple could still decline; the fallback is to ship without the feature while the request is pending.
  4. Guideline 4.10: built-in capabilities can't be monetized, and the Screen Time APIs are named explicitly. Guideline 3.1.1: anything unlocked for money must use in-app purchase [22]. Charge for the app's own features, never for "unlock blocking".
  5. Guideline 5.5: MDM is for enterprise, education and limited parental cases [22]. Not a route for a consumer MVP.

12.3 Privacy and law

  • On-device only: rules, usage minutes, tokens and package names never leave the phone, and no analytics event contains an app identity.
  • Consent and exit: a one-screen explanation before each permission, and a "Turn off" that removes everything.
  • Adults only in the MVP. A child or family mode would bring children's-privacy law: the amended US COPPA rule (fully enforceable since 22 April 2026) [115], US state app-store age laws such as the one in force in Texas [116], and the UK Children's Code, which requires an obvious sign to the child when monitoring is on [117].

Gaps a new product can fill: a task that is verified honestly, no paywall on unlocking, and a real Android version (most exercise competitors are iPhone-only).

14Recommendations and roadmap

Ship the MVP in section 4: real blocking (Level 3) with an opt-in Strict mode (Level 4). A timer with reminders adds little that phones don't already do. Skip Level 5. Never promise "can't be bypassed".

14.2 Long-term maintainability

  • Keep all rules in one shared engine. Native code mirrors only "what's blocked now", through one tested contract (the plan).
  • One shared Swift file linked into every extension, with nothing heavier than Apple's frameworks.
  • Gate features by OS version at runtime: 17.4 (thresholds), 26.4 (menu), 26.5 (open app, token expiry).
  • Rerun the device pass on every iOS and Android beta. Both platforms changed this area in every 2025–2026 release.
